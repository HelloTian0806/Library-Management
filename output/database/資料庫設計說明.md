# 圖書管理系統資料庫設計

本設計延續使用案例、UI／AC 循序圖與類別圖，以現有 DAO 使用的 `members`、`books`、`borrows` 為基礎。這是目標設計，未連線檢查既有資料庫，也未執行建表或修改應用程式。

## 設計範圍與關聯

| 主表 | 明細表 | 關聯 | 規則 |
|---|---|---|---|
| members | borrows | 1 對 0..多 | 每筆借閱必須屬於一位會員 |
| books | borrows | 1 對 0..多 | 每筆借閱必須對應一個書目；一次借閱一冊 |

管理者也是 members 的一種角色，不另建管理者資料表。books 表示同一 ISBN 的書目與合計館藏數量，不表示單一實體書冊。借閱紀錄保留歷史，外鍵採 RESTRICT，避免刪除仍被歷史紀錄引用的會員或書籍。

## 資料字典

### members：會員與管理者

| 欄位 | 型別 | 可空值 | 鍵／預設 | 說明 |
|---|---|---|---|---|
| id | INT | 否 | PK、自動編號 | 對應 Member.id |
| account | VARCHAR(64) | 否 | UNIQUE | **新增設計**：獨立登入帳號 |
| name | VARCHAR(100) | 否 | | 姓名 |
| email | VARCHAR(254) | 否 | | 聯絡信箱；本版不強制唯一 |
| password | VARCHAR(255) | 否 | | 保留程式欄位名稱，只存密碼雜湊 |
| phone | VARCHAR(30) | 是 | NULL | 電話，不使用數值型別 |
| role | VARCHAR(16) | 否 | MEMBER | **新增設計**：MEMBER／ADMIN |
| status | VARCHAR(16) | 否 | ACTIVE | **新增設計**：ACTIVE／SUSPENDED |
| created_at | DATETIME | 否 | CURRENT_TIMESTAMP | 建立時間；現有 Member.createdAt 是 LocalDate，若保留時間需調整映射 |

account 在儲存前去除頭尾空白，採不區分大小寫的帳號政策；資料庫 collation 同時不區分重音字元。註冊者無法自行指定 ADMIN 或停權狀態，角色變更必須由管理功能授權。密碼雜湊由應用層處理，不將原始密碼寫入資料庫。

### books：書目與庫存

| 欄位 | 型別 | 可空值 | 鍵／預設 | 說明 |
|---|---|---|---|---|
| id | INT | 否 | PK、自動編號 | 書目識別碼 |
| isbn | VARCHAR(13) | 否 | UNIQUE | ISBN-10／ISBN-13，先移除空白及連字號 |
| title | VARCHAR(255) | 否 | | 書名 |
| author | VARCHAR(255) | 否 | | 作者文字；本版不另做多作者關聯 |
| publisher | VARCHAR(255) | 是 | NULL | 出版社 |
| category | VARCHAR(100) | 是 | NULL | 分類文字 |
| total_quantity | INT | 否 | 0 | 館藏總數 |
| available_quantity | INT | 否 | 0 | 可借閱數量 |

庫存必須符合 `0 <= available_quantity <= total_quantity`。新增書籍時，應用程式在同一 INSERT 將兩個數量設為相同值。SQL 允許 0 冊作為保留書目；現有 BookService 新增時要求大於 0，是較嚴格的應用規則。ISBN 的長度由資料庫限制，合法字元與檢查碼由應用層驗證。

### borrows：借閱歷史

| 欄位 | 型別 | 可空值 | 鍵／預設 | 說明 |
|---|---|---|---|---|
| id | INT | 否 | PK、自動編號 | 歸還操作使用的唯一借閱識別碼 |
| member_id | INT | 否 | FK → members.id | 借閱會員 |
| book_id | INT | 否 | FK → books.id | 借閱書目 |
| borrow_date | DATE | 否 | | 借閱日期 |
| due_date | DATE | 否 | | 應歸還日期，不早於借閱日 |
| return_date | DATE | 是 | NULL | 歸還日期，沿用現有 DAO |
| returned_at | DATETIME | 是 | NULL | **新增設計**：使用案例要求的實際歸還時間 |
| status | VARCHAR(16) | 否 | BORROWED | BORROWED／RETURNED／OVERDUE |

歸還時同時設定 `status='RETURNED'`、`return_date`、`returned_at`；未歸還時兩個歸還欄位皆為 NULL。所有時間採同一約定時區（本專案建議 Asia/Taipei）；DATETIME 本身不包含時區。借閱天數由業務層決定；現有程式使用 14 天，原使用案例未指定，SQL 不將其固定。

OVERDUE 沿用現有 enum。逾期不會因日期經過而自動改變：需由排程更新，或查詢時依 `return_date IS NULL AND due_date < CURRENT_DATE` 計算顯示狀態；若選後者，篩選也必須使用日期条件，避免僅依儲存狀態查詢而漏列。

## 借閱與歸還交易

以下是應用層交易規格，不是已執行的資料庫操作：

1. 借閱：開始交易，讀取並鎖定會員，確認 ACTIVE；以 `UPDATE books SET available_quantity=available_quantity-1 WHERE id=? AND available_quantity>0` 扣庫存；必須檢查影響筆數為 1，否則回復。接著新增 borrows，成功才提交。會員狀態管理需遵循相同鎖定規則。
2. 歸還：開始交易，以 `SELECT ... FOR UPDATE` 鎖定指定 borrows.id；確認未歸還。使用含 `status IN ('BORROWED','OVERDUE')` 及 `return_date IS NULL` 條件的更新，同時寫入狀態、日期與時間；影響筆數必須為 1。再增加 books 可借數量（條件為低於總數），影響筆數也必須為 1，否則整筆回復。
3. 取消不寫入任何資料。所有讀寫使用同一交易連線；失敗或受影響筆數不符都回復，不能只在 SQL 丟例外時回復。並行操作遇到死鎖時，應回復後有限次重試完整交易。
4. 調整總館藏時，需鎖定該書目並同步調整可借數量，確保總數不小於借出數。本版理想不變式為「可借數 = 總數 - 未歸還借閱數」；跨資料表一致性不能由本檔的單列 CHECK 自動維護。

## 條碼與多冊館藏

本版採三表模型：掃描 ISBN 找到 books，再由管理者依會員確認實際 borrows.id 後歸還，不能直接將該書第一筆紀錄當作歸還對象。這是為補足原使用案例歧義而提出的 UI 設計決策。

若要求「每冊有唯一條碼、掃描即可準確歸還」，下一版應新增 `book_copies(id, book_id, barcode UNIQUE, status)`，並讓 borrows 參照 copy_id；另須限制每冊最多一筆未歸還借閱、建立既有紀錄的冊別映射及庫存遷移。本版 ER 圖與 SQL 未混入尚未實作的逐冊模型。

## 與現有程式的銜接

- Member、MemberDAO 新增 account、role、status；目前 addMember 未寫 account，不能直接套用目標結構而不調整程式。登入讀取須取得密碼雜湊及帳號狀態。
- Borrow 與歸還 DAO 新增 returned_at；目前只更新 return_date 的方法不符合目標歸還限制，狀態及歸還時間必須一次更新。
- BorrowService 需檢查扣庫存、新增借閱、更新歸還與回補庫存的結果；現有程式未完整檢查，光加上表格限制不足以完成交易正確性。
- BookDAO.updateBook 目前沒有更新館藏數量；若實作館藏調整，須依上面的庫存交易規則處理。
- 現有 BookDAO.findAll 使用完整名稱 library_management.books；若測試另一個 schema，須同步調整此硬編碼。
- 保留 INT 以對應現有 Java int；建構子、DTO、SQL 與畫面要一併更新。這次只交付設計成果。

## 交付與驗證

`schema.sql` 適用全新空白 schema，未包含 CREATE DATABASE、DROP 或 ALTER，也不是既有資料的遷移腳本。現有資料上線前需盤點重複帳號／ISBN、孤兒外鍵、歷史日期與庫存，再另寫 migration。

已檢查圖表欄位與 SQL 一致、主外鍵與索引定義及 ER 圖結構；未在 MySQL 執行，因此尚未完成引擎層建表與並行交易測試。

語法參考：[MySQL CHECK 限制](https://dev.mysql.com/doc/refman/8.0/en/create-table-check-constraints.html)（8.0.16 起支援強制檢查）、[MySQL 外鍵限制](https://dev.mysql.com/doc/refman/8.0/en/create-table-foreign-keys.html)。設計目標為 MySQL 8.0.16 以上及 InnoDB，實際伺服器版本尚未確認。
